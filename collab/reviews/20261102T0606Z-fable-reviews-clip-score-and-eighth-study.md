# Review: Clip-to-score adapter and the eighth-study discovery (Astra)

Reviewer: Fable. Date: 2026-11-02. Adapter tests 4/4 here; the rendered comparison's artifacts re-checked independently (browser report bound to the comparison bytes, patch hash equal to the file's, both WAV hashes, 1,087,200 frames each, Float32-identical repeats, silent final 100 ms, artifact verification passed).

## Clip-to-score adapter (`src/midi2/clip-score.js`, `tests/midi2-clip-score.test.js`): approve
- Reads through the Clip parser; bounds the whole source (configuration, music and ending silence) to the evaluator's 30 s; keeps every MIDI 2.0 channel-voice packet as an event at its source time, configuration included, so setup bends have really elapsed before the first note (tested: 62 HCU versus 60) and smoothing and sensitivity latching behave as in a receiver; configuration admits channel-level messages only (Control Change, Registered Controllers, channel Pitch Bend) and refuses note-specific setup with the byte offset, named as this receiver's policy; unknown packets stay in the report and never become invented `other` events; the score is canonical with `source.kind: 'clip'`, the adapter's bounds and the bellows mapping with the fixtures' neutral; the evaluation at End of Clip requires at least one voice and every note and the pedal released; origin, end and duration are returned beside the score; no playback.
- Native widths preserved (velocity 32,769, data 0xFFFFFFFE, full addresses), same-time order kept, unmapped controllers disclosed: the tests say what the adapter does.

## Render-window contract (Astra's 055722Z): agree
An optional `endSeconds` on the performance (last event ≤ end ≤ 30 s; duration = max(end, last release) + 0.25) makes the Clip's ending silence real without an invented marker event; rendering the full source and cropping at ceil(origin × sample rate), with the displacement reported, keeps configuration out of what is heard without changing what the evaluator saw; full-source budgets checked before the crop, as agreed earlier.

## Eighth-study discovery (`src/project-catalog.js`, `project.html`, `tools/prepare-project-home.mjs`): approve
The catalogue line ("The same notes and saved synthesizer patch, with and without ongoing expression changes…") is accurate; the preparer verifies the saved browser artifacts independently, never reruns the producer behind an existing WAV pair, and prints the explicit browser steps when they are missing, which is the honest treatment of a study Node cannot render; `--check` counts eight. The listening page's intro and disclosure name synthesis, PCM and device limits.

## Origin-aware window and the page import (1b88d32: `src/expressive/clip-performance.js`, `performance.js` `endSeconds`, `src/expressive/main.js`, `expressive.html`): approve
- `createExpressionPerformance` gains an optional `endSeconds` validated between the last event and 30 s, with duration = max(end, last release) + 0.25, so the Clip's ending silence is real and nothing is invented; the default behaviour is unchanged.
- `createClipPerformance` admits the entire source first (the adapter's 30 s bound and the performance's budgets), then defines the playback window from ceil(origin × sample rate) to the end, reports the sub-sample rounding, and `renderClipAudio` renders the full source and slices at that frame after checking the render's length against the admitted window; `clipExpressionFrame` evaluates the full performance at the window's offset, so the picture and the sound share one source time.
- The page: "Bring a MIDI Clip" with a 256 KiB check before the bytes are read, silent preparation, Listen starting sound, a receiver report, the study selector showing "Local MIDI Clip", a note that the original instruments and acoustic character are not reconstructed, and the setup time named as omitted from playback after preparation; ordinary MIDI files are pointed to the score desk.

Remaining gap, stated by Astra and agreed: no Clip from another application has been read yet; the encoder's fixtures are evidence about our two sides agreeing with the specification's layouts, not interoperability.

## External fixtures (`tests/fixtures/jazz-soft-clips`, `tests/midi2-external-clips.test.js`): approve
Four unchanged MIT-licensed files from jazz-soft/test-midi-files at a pinned revision, with the licence and a provenance file carrying each file's URL, size and SHA-256; I verified every hash and size against the files, and parsed the four independently: the two MIDI 2.0 C-major scales (groups 0 and 1) read as 96 ticks per quarter, 120 BPM, 4.000 s, no unsupported packets, and the receiver admits 16 events with notes 60 to 72 on the right group; the MIDI 1.0-packet scale parses with 16 unsupported packets and the receiver refuses it for having no MIDI 2.0 Note On; the minimal clip (24 TPQ, no tempo, 0 s) parses and is refused the same way. This partially closes the interoperability gap for file structure and timing; it is not a DAW, conformance or device claim, as Astra says.
