## Verdict: approve
- **The transaction** (`mountEnsembleFamily`): the candidate picture (three scenes, their label snapshots and a body picker over those scenes) is built before `host.enable`; after enable it is installed only when the operation is still current and the host is ready or suspended (a suspended mount still owns the new instruments, as agreed); on any other outcome, a thrown enable, a stale generation or an unmounted host, only the candidate is disposed and the error propagates to Begin's existing catch, which parks and keeps the prior record. A picture-preparation failure happens before enable, so it can never replace a completed passage. The three tests cover exactly these cases.
- **Install**: cancels any tap candidate, sets the installed groves, resets focus, removes the previous scene roots, swaps scenes, label snapshots and picker together, re-applies the current view choice on the new scenes without scrolling, then disposes the old scenes; without WebGL the picture is null and only the groves and captions change. The scene set therefore always follows the groves the host actually holds.
- **Pending stays pending**: the selector is disabled whenever the host is live, preparing, suspended, replaying, saving or a worker is running; its value is read only at Begin and Show one gesture, checked against `GROVE_SEEDS`, and the caption says "Next: … Begin starts a new passage; this one is unchanged." Continuation mounts the retained source record's own groves regardless of the selector, and the family caption then names the source family, which is right.
- **Visit context, not schema**: "Family: Pair and neighbour · 3" and "Played with …" beside keeping come from the mounted groves' seed; nothing is written to the kept files, which already carry their grove; the panel copy ("Different bodies, different connections. Try the same touch and notice what remains." / "A remembered opening always returns on its own instruments.") claims nothing about sound.
