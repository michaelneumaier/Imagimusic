# Review: shared-gesture scheduling in the inverse transport (Astra, working tree: `src/inverse/transport.js`, `tests/inverse-transport.test.js`)

Reviewer: Fable. Date: 2026-11-02. Transport tests 6/6 here.

## Verdict: approve
- **One audio-clock transaction**: `schedule` creates and connects every source first, then fixes one origin (`currentTime + lead`, 30 ms for a gesture, 0 for a touch) and starts each source at origin plus its offset; any failure stops, disconnects and drops every entry of the new phrase and rethrows, so a phrase either exists whole or not at all. A single touch is the same path with one event and no lead, so the two cannot diverge.
- **Upcoming sources reserve slots**: future entries sit in the active set, so the eight-strike cap covers them and a direct touch can use only the remaining slots; the snapshot reports `active` and `strikes` for entries that have started and a separate `pending` count, so the picture never shows a response that has not begun; the level ramp treats a state with no sounding entry as instant, which is right because nothing is heard to step.
- **Starts from quiet, validated, gated**: `playGesture` requires a mounted instrument and a running context (no resume), validates 1..8 events with bodies 0..2 and non-decreasing times within 0..8 s, and refuses to start while anything is active or pending, so a gesture never stacks on a ring; Quiet retires active and future entries alike.
- **Interface**: events are `{ body, at }` in seconds from the first touch; the score export `inverseGestureTransportEvents()` produces exactly that from the frozen gesture, so the page and the offline harness share one authored source.
Nothing to change. Native evidence to come: the gesture ending in silence, Quiet mid-gesture (including before the second moment has started), and a touch refused while slots are reserved.

## Addendum: page integration and offline gesture harness (approve)
- **Page**: the pads, direct taps, the opener and preparation treat "occupied" as active plus upcoming, so a candidate switch or an open cannot land under a scheduled touch and the ninth-touch message says "ringing or upcoming"; the ring line reads "N ringing · M upcoming / 8 touches"; "Hear a gesture" is enabled only with an instrument, armed, running, not busy and nothing occupied, and calls `playGesture` with the score's events inside a try so a refusal is shown rather than thrown; the help line states the three touches and the settle time from the instrument's own duration; the gesture never touches the last-touch memory. Visible wording is Astra's and claims nothing beyond "the same three touches on every anatomy".
- **Harness** (`tests/inverse-gesture-render`): the default target from the kept fixture is searched with the page's options, both candidates prepared at 8 kHz, and each rendered through the real transport over a real OfflineAudioContext in three modes: the whole phrase, Quiet at 0.256 s (asserting one sounding and two upcoming sources at that moment, then none), and Quiet before the origin (all zeros). Every output sample is compared to the sample-aligned sum of the prepared strike PCM at the scheduled frames with tolerance 1e-7, the tail after the stop or the natural end must be exactly zero, upcoming touches must not appear in the snapshot's strikes, and the first half second's right-minus-left energy is reported for comparison with the note's numbers. Reading rule: an error above tolerance in the full mode alone would point at sub-sample source start timing in that browser rather than at the transport, and the result names the browser.
- **Validator correction** (Astra): the exported gesture validator iterated with `forEach`, which skips holes, so `new Array(3)` with span 0 passed; it now iterates by index and requires each own index, with refusal tests for `new Array(3)` and a holed array. The fixed authored score was never affected.
