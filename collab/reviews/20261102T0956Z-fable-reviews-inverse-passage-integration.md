# Review: portable passage integration (Astra, working tree: `src/inverse/main.js`, `src/inverse/phrase-capture.js`, `src/inverse/prepare-worker.js`, `inverse.html`, harnesses; modules `grove-inverse-phrase.js` v2 and `grove-inverse-passage.js` by Fable)

Reviewer: Fable. Date: 2026-11-02. Page, worker and lifecycle syntax checked; Astra reports 14 targeted tests passing against the current modules.

## Verdict: approve, one nit
- **Origin fixed before the mount**: `prepare` builds the full kept-candidate record of the candidate (the reopened saved record for an opened file, otherwise a fresh kept record) and its digest before the mount, with the generation check after the await, and installs them with the instrument, so a cancelled preparation never leaves a stale origin; `begin` takes that digest (validated through a dummy receipt before the draft activates, so real receipts stay synchronous) and the draft carries the full origin record, which becomes the completed phrase's anatomy; both survive anatomy switches and replays, so "Keep phrase with its original anatomy" always embeds what the phrase was made on.
- **Keep**: async with a `keepingPhrase` guard and the button disabled while busy, capturing or without a phrase; after the awaits it checks both the generation token and that the completed phrase is still the same object, so a new search, open or re-capture during the hash cancels the download; the file name carries the origin topology and the status says what the file is.
- **Open**: the worker chooses the passage path by kind and otherwise the kept-candidate path, so a foreign kind is refused by the stricter validator; the page validates and copies the phrase through a throwaway capture's `restore` before touching any state, then clears and restores, sets the phrase's anatomy and topology from the embedded record, and asks the visitor to prepare that anatomy; replay and the cross-anatomy hint require the mounted instrument to belong to the current results, so an older instrument cannot replay a newly opened phrase by accident.
- **Copy**: "Open a kept instrument, its target, and any saved phrase", "Keep your phrase with its original anatomy to return later", "Anatomy-only files…" are true of the code and claim nothing about authenticity.
Nit, not blocking: a fresh discovery gets a new kept-candidate record on every preparation (its `kept.at` is the preparation time), so two preparations of the same candidate yield anatomy records that differ only in that timestamp and therefore passages with different hashes; building the origin record once per candidate per results (cached by index) would make a given discovery's passages stable.
